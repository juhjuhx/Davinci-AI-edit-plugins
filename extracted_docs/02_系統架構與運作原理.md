# 02_系統架構與運作原理

## 1. 系統架構與元件解耦 (System Architecture)
Smart A-Roll v4.0 採用前端 (WebUI)、後端 (Flask API Server) 與 AI 推理引擎分離的分層架構：

*   **前端 WebUI (Single-Page App)**:
    *   基於純 HTML5/Vanilla CSS/JavaScript 開發（無底層大框架，輕量且載入極快）。
    *   提供視覺化的**音訊波形時間軸**，將不同狀態的說話片段以顏色著色（例如：綠色為保留，紅色為剪除，橙色為填充詞，藍色為靜音）。
    *   整合影片即時預覽功能（點擊時間軸會發送 API 請求，實時渲染並回傳 1/4 解析度 frame 的 base64 影像，不卡頓）。
    *   支援拖曳面板佈局、快速鍵操作（如 Q/W 快速剪切、B 鍵切換剃刀模式）。
*   **後端 Flask API 伺服器 (api/app.py)**:
    *   運行於本地 `127.0.0.1:8888`。
    *   負責路由請求、調用本地文件瀏覽器、影片預覽格提取，並提供背景佇列服務。
    *   利用 **SSE (Server-Sent Events)** 與前端保持通訊，實時推送 AI 分析進度與日誌資訊。
*   **工作佇列與背景 Worker (workers/analyze_worker.py)**:
    *   單執行緒背景佇列，防止多個分析任務同時執行造成 VRAM/RAM 崩潰。

## 2. AI 推理與分析引擎運作原理 (Inference & Analysis Engine)
影片導入後，分析引擎 (`core/analyzer.py`) 會依次執行以下處理階段：

```
[輸入影片] ──> [FFmpeg 提取音訊 (WAV)] ──> [faster-whisper 語音轉錄] 
                                                    │
[FFmpeg 視訊切片與匯出] <── [人工/自動套用] <── [規則匹配 & LLM 二次確認] <── [Librosa 靜音偵測]
```

### 2.1 音訊特徵提取 (Audio Extraction)
*   呼叫 FFmpeg 將影片的音訊軌道快速提取為單聲道、16000Hz 採樣率的 PCM WAV 格式暫存檔（Whisper 模型的最佳輸入格式）。

### 2.2 語音識別與信心度正規化 (Speech-to-Text & Confidence)
*   **轉錄器**：使用 `faster-whisper`（CTranslate2 優化版 Whisper），支援從 `tiny` 到 `large-v3` 模型。
*   **信心度正規化**：Whisper 輸出的 `avg_logprob`（平均對數機率）數值區間較難直觀使用。本工具使用 **Sigmoid 函數**將其映射為 `0.0` 至 `1.0` 的信心度區間：
    $$Confidence = \frac{1}{1 + e^{-k \cdot (avg\_logprob - threshold)}}$$
    *(預設參數: $k=4.0$, $threshold=-0.5$, 當信心度低於 0.2 時標記為 UNCERTAIN 片段)*。

### 2.3 規則引擎多維標記 (Rules Engine)
*   利用高效率的正則表達式 (Regex) 對轉錄文本進行多維度分析：
    1.  **填充詞/口頭禪 (Filler)**：匹配如 `(嗯+|啊+|呃+|那個|然後|基本上)` 等。
    2.  **重複詞 (Repeat)**：匹配在短時間內重複出現的兩字以上詞彙（如 `我們今天...我們今天`）。
    3.  **自我修正 (Correction)**：匹配如 `(不對|不是|應該是|我是說)`。
    4.  **喉音與清嗓 (Throat)**：匹配 `(嗯哼|嗯嗯|啊啊)`。
    5.  **剪輯暗號 (Cue)**：
        *   **拍手指令 (clap_cue)**：錄影時拍手產生高波峰音量，或講者說「拍手」，用來做時間標記。
        *   **剪輯指令 (cut_cue)**：講者口頭發出的指令，如 `(cut|剪這裡|重來|NG)`，直接將該片段標記為高優先級 CUT 片段。

### 2.4 本地 LLM 二次確認 (LLM Verification)
*   **目的**：Regex 規則有時會誤殺正常語句（例如「然後」在部分語境下是正常連接詞）。
*   **機制**：當啟用 LLM 且模型就緒時，系統會篩選出被規則引擎判定為「填充詞/猶豫/不確定」的片段，發送給本地運行的 GGUF LLM（如 Qwen2.5-0.5B）。LLM 會根據語境判定該片段是應保留（KEEP）還是剪除（CUT），從而降低誤判率。
*   **核心技術**：利用 `llama-cpp-python` 載入 GGUF 模型，並在 Windows 下透過 `_fix_dll_path` 動態載入 CUDA 相關 DLL，確保 GPU 加速順暢。

### 2.5 靜音與停頓偵測 (Silence Detection)
*   利用 `librosa` 計算音訊的 Root Mean Square (RMS) 能量特徵。
*   若音訊片段能量低於設定閾值（預設 `0.006`）且持續時間大於設定值（如 `0.5` 秒），則將該區間標記為 **SILENCE（靜音）**，作為切除停頓的依據。

## 3. DaVinci Resolve 深度整合機制 (DaVinci Integration)
Smart A-Roll 的一大特色是能與 DaVinci Resolve 進行無縫 API 連接 (`core/resolve.py`):

1.  **建立連線**：
    腳本 `apply_to_resolve.py` 運行在 Resolve 內部控制台時，會導入 `DaVinciResolveScript`，取得目前開啟的專案 (`GetCurrentProject()`) 與目前活動的時間軸 (`GetCurrentTimeline()`)。
2.  **幀率同步**：
    自動讀取 DaVinci 時間軸的精確幀率 (timelineFrameRate)，並將 AI 分析報告中以秒為單位的時間戳，精確轉換為時間軸上的**訊號幀數**：
    $$\text{Frame\_Number} = \text{Time (seconds)} \times \text{FPS}$$
3.  **時間軸軌道匹配**：
    讀取視訊軌道（預設為軌道 1）上的所有影片剪輯 (Clips)。
4.  **套用屬性與彩色 Markers**：
    AI 片段的時間範圍會與軌道上的剪輯位置比對，一旦重合，腳本會對 Clip 進行操作：
    *   **修改剪輯顏色 (Clip Color)**：保留片段標記為 `Green`，剪除片段標記為 `Red`。
    *   **添加時間軸標記 (Markers)**：對於被判定為 CUT/FILLER/REPEAT 等無效片段，在對應 Clip 起始位置新增一個帶有對應顏色的時間軸標記 (Marker)。
        *   **紅色 Marker**：指令剪除 (CUT)
        *   **橙色 Marker**：填充詞 (FILLER) / 自我修正 (CORRECTION)
        *   **黃色 Marker**：重複詞 (REPEAT) / 猶豫停頓 (HESITATION)
        *   **藍色 Marker**：長靜音 (SILENCE)
        *   **綠色/紫色 Marker**：正常保留或不確定片段。
    *   Marker 內會自動填入該片段的**類型、分析原因、以及前 60 個字的轉錄文字**，方便剪輯師直接滑鼠懸停查看。

## 4. FFmpeg 視訊處理管道與 GPU 加速 (FFmpeg GPU Pipeline)
除了套用到剪輯軟體，工具本身也支援直接匯出：

*   **自動 GPU 編碼器偵測 (NVENC)**：
    初始化時，`FFmpegRunner` 會自動執行一次 `ffmpeg -encoders`，掃描系統是否支援 NVIDIA 硬體加速編碼器 `h264_nvenc`。
    *   若**可用**：啟用 `h264_nvenc`，並套用 VBR (可變碼率) 搭配 CQ (CRF) 的高速 GPU 編碼。
    *   若**不可用**：自動 fallback 至 CPU 編碼器 `libx264`，確保相容性。
*   **無損快速剪輯 (Stream Copy)**：
    若使用者選擇此模式，FFmpeg 會以 `-c:v copy -c:a copy` 的方式直接截取保留的影音串流片段，並透過 concat demuxer 重新合併。這項操作**不需要重新解碼和編碼**，一個數 GB 的影片可在幾秒鐘內剪輯完成，且畫質完全無損。
*   **音訊增強濾鏡鏈 (Audio Enhancement)**：
    支援在重編碼時套用音訊處理：
    1.  `highpass`：過濾特定頻率（預設 80Hz）以下的低頻電流雜音與底噪。
    2.  `lowpass`：過濾高頻刺耳杂音。
    3.  `loudnorm`：進行響度標準化（目標響度預設 -16.0 LUFS），確保影片音量均勻。
